## Iteration A4 - domain neutrality

- 2026-11-11T04:05:00.000Z Scope: two differently shaped domains, each with its own good reference written from the domain (not by renaming Blog), to expose blog-isms in the harness. `support` is a root resource `/api/support-tickets` (entity `Ticket`, `SupportContext`; writable `subject` string, `priority` int 1-5, `escalated` bool, `category` string from a closed set; server-owned `viewCount` int and `lastViewedAt` timestamp, both updated by GET through an atomic `ExecuteUpdateAsync` so counters never touch the ETag concurrency token). `logistics` is parent/child: `/api/warehouses` (entity `Depot`, writable `code`, `capacityCubicMeters`, server-owned `lastAuditAt` timestamp) and `/api/warehouses/{warehouseId}/shipments` with flat item route `/api/shipments/{id}` (entity `Consignment`, DbSets `Depots`/`Consignments`, body parent field `warehouseId`, writable `reference`, `weightKg` decimal with at most 2 decimals, `fragile` bool, server-owned `downloadCount`). Descriptors `support.json`, `logistics.json`, `logistics-root.json`; subjects under `evals/subjects/support` and `evals/subjects/logistics`.
- Process: the harness was changed before the first run for the blog-isms I could see by reading it; afterwards I temporarily restored the A3 harness files and re-ran to confirm which ones bite (evidence below), then restored the new files. Nothing was discarded.
- Blog-isms found and fixed (harness unless stated):
  1. Descriptor loader required 3 distinct samples for every field; a boolean has two values. Confirmed: support.json rejected ("escalated has 2 distinct samples"). Now boolean needs 2, and a domain needs at least one non-boolean field so scenarios can build different bodies.
  2. `childCollectionRoute` only substituted the literal `{parentId}`; any other placeholder (logistics uses `{warehouseId}`, matching the real route) left the braces in the URL. Confirmed: 404 for every child scenario. Now any single `{name}` placeholder is replaced.
  3. Representation checks compared `GetRawText()` of the response with the descriptor sample, so a decimal sample `12.50` failed against a server that returns `12.5` or `12.50` differently, and a string failed if escaped differently. Confirmed: `weightKg should be 12.50`. Now strings compare by value, numbers by decimal value, booleans by kind.
  4. `CanonicalHash` wrote number samples with their raw spelling, so `12.50`, `100.00` and `12.5` hashed differently. Now numbers are canonicalised as invariant decimals with trailing zeros dropped (`12.5`, `100`, `0.05`); the logistics reference does the same with `0.##`.
  5. `BumpServerOwned` only did `col = col + 1`, which is wrong for timestamps (it wrote `2027` into a DateTime column; confirmed: `FormatException: String '2027' was not recognized as a valid DateTime`). `ServerOwnedField` gained `kind` (`counter` default, `timestamp`); a timestamp is set to now plus one day through a bound parameter, `DateTime` or `DateTimeOffset` chosen from the model property.
  6. Server-owned scenarios assumed the server-owned field lives on the resource under test. `lastAuditAt` lives on the parent. `ServerOwnedField` gained `owner` (`resource` default, `parent`); for parent-owned fields the scenarios check the parent ETag and the child ETag are unchanged, that the PUT with the pre-bump If-Match still works, and that the field is absent from the parent GET.
  7. Test harness: `Subject.BlogSources` and a hard-coded `blog.json` in the mutant theory; sources now come from `subjects/<name>` (descriptor file name without `-root`), and domains are discovered by directory scan.
  8. Reference bug (no real ones found): none. Both references passed all groups on the first run once the harness was fixed.
- Assumptions that held and need no change: field order in the canonical JSON is id, parent id, then writable fields in descriptor order (mixed-type orders in support and logistics hash identically in reference and harness); camelCase field names; `id` property name; item route as `collectionRoute/{id}` also works when the child's flat route differs from the nested one; entity class, DbSet and table names are only ever read from EF metadata.
- Residual limits (not fixed, recorded): `create-invalid-body` and `replace-invalid-body` omit `writableFields[0]`, so the first field of every descriptor must be one the server cannot default (a string). Samples for ints do not cover validation ranges (priority 1-5 uses 2, 4, 5). The harness bumps a timestamp forward by one day; a server that rejects future timestamps would not be an issue because the write is out of band.
- Ambiguity (protocol.md, safest interpretation chosen): "fixed field order" does not say whose order. Chosen: id, parent id, then client-writable fields in descriptor order. Numbers: protocol is silent; chosen invariant decimal, no exponent, no trailing zeros.
- Mutants: `mutants.json` entries take an optional `domain` (default `blog`). Ported to logistics (all pass on first run with the same expected sets as the blog originals): `logistics-replay-409` (create; fails create-replay-after-put-returns-current-representation, create-replay-of-tombstoned-is-gone, create-replay-returns-same-success), `logistics-put-stale-same-body-412` (replace; fails replace-identical-body-with-stale-if-match-succeeds, replace-retry-with-stale-if-match-same-body-succeeds), `logistics-delete-404-on-repeat` (delete; fails delete-retry-is-no-content).
