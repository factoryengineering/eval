3. Why values-only moved

StepWhat changedWhy
1 to 2 Skill text: "Do not use AsNoTracking(); project values from read-only queries." became "Read-only queries project values, never entities, so nothing is tracked: never write AsNoTracking()." A bare prohibition lost to the model's habit of adding AsNoTracking() to anything described as read-only. Giving the reason raised the rate from 0.33 to 0.60.
2 to 3 Grader only: read-only-values now accepts tuple projections such as select (post.Title, post.Views). Every remaining failure was a correct answer the regex did not recognise. The skill text did not change, and the measured rate rose from 0.60 to 1.00.

Step 3 is a measurement fix, not a skill improvement. Of the 0.33 to 1.00 total, the skill-text change accounts for the 0.33 to 0.60 portion; the rest is the grader being corrected.
