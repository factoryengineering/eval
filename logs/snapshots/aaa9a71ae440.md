---
name: ef-linq
description: Opinions for LINQ queries against an Entity Framework Core DbContext. Not for migrations, model configuration, or raw SQL.
---
Rules for EF Core LINQ queries:
- Filter only in the database: never call user-defined C# helper methods in a query, and never filter results after `ToList()` or `ToListAsync()`. Use built-in translatable members such as `StartsWith`.
- Use async terminals such as `ToListAsync(cancellationToken)` and pass the `CancellationToken`.
- Use `AsSplitQuery()` when `Include`-ing more than one collection.
- Assign the query to a `var`, then execute it in a separate statement with `await`.
- Never name the awaited result after the query's range variable: `from post in posts` then `var post = await ...` does not compile.
- Prefer query syntax (`from ... select`) over extension-method syntax.
- Use meaningful words for variable and lambda parameter names.
- Read-only queries project values, never entities, so nothing is tracked: never write `AsNoTracking()`.
